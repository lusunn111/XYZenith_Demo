## 实施阶段

| 阶段 | 工作 | 完成依据 |
| --- | --- | --- |
| 1. 仓库与接口 | 建立目录，约定任务创建、查询和结果接口 | 各模块有明确职责，前后端字段一致 |
| 2. H3 兼容性验证 | 按用户要求采用最新稳定版 SGLang，确定受支持驱动或前向兼容方案，检查依赖和内存 | 在指定 GPU 上导入环境并完成必要算子验证，保留版本记录 |
| 3. 模型与首次生成 | 下载固定版本的文本生成所需权重，运行短视频任务 | 输出可播放文件，记录参数、显存、主机内存及耗时 |
| 4. 前端与业务后端 | 实现提示词输入、状态、播放与计时，持久化任务和队列 | 模拟接口可验证交互，模拟结果标记清楚 |
| 5. VPS 与 A100 联调 | 配置反向连接、健康检查和结果回传 | VPS 可以调用真实推理服务并访问视频 |
| 6. 公网验收 | 真实提示词生成、排队、失败反馈、页面刷新和服务重启检查 | 从浏览器完成真实生成，任务记录及结果一致 |

第 4 阶段可以与第 2、3 阶段并行。推理配置确认后再固定前端展示的模型能力和生成规格。短视频先完成真实生成，再优化性能。

## MiniMax-H3 部署约束

用户后续明确希望安装最新版，当前目标按最新稳定版 SGLang 制定，安装时固定实际版本。SGLang 当前默认安装路线已迁移至 CUDA 13。现有驱动 550.54.14 与默认运行栈存在兼容约束，优先考虑由管理员升级至所选 CUDA 栈支持的驱动分支。全局驱动或 CUDA 变更需要用户确认。

NVIDIA 提供适用于数据中心 GPU 的前向兼容包，可在应用范围加载新版用户态驱动库。A100 属于适用硬件，但当前官方支持矩阵没有列出 R550，且明确未列出的过期分支不属于受支持目标，因此该机上的前向兼容路线需要独立实测。服务器已有 Docker 和 NVIDIA Container Toolkit，当前账号访问 Docker socket 时返回权限不足。具体部署方式待用户决定。

官方 FL2VA 权重分支覆盖文本到音视频与首尾帧条件任务。按官方文件清单求和，该分支约 144 GB，包含文本编码器、生成模型和音视频编码解码组件。下载及环境预算暂估 250–300 GB，实际以所选版本和下载清单为准。固定权重版本并限定需要的分支，避免重复下载其他任务分支。

双 40 GB A100 的精度、GPU 分配与 CPU 卸载方案仍待实测。共享 NFS 上的逐层权重读取可能带来额外等待，低显存配方不能直接移用其他服务器的性能数据。若需要更换量化权重或降低生成规格，先把影响与用户确认。

## 数据与部署约定

`frontend/src` 保存前端代码，`backend/app` 保存业务后端，`inference/configs` 保存验证过的推理配置，`deploy/vps`、`deploy/gpu` 和 `deploy/tunnel` 分别保存部署配置。

业务后端先采用单实例任务队列和持久化任务状态。提交请求返回任务编号，浏览器查询实际执行阶段。视频先在数据盘生成，完成后上传 VPS，VPS 设置明确的结果保留时长和容量限制，具体数值在部署阶段确认。

计时分别记录排队、GPU 侧生成、结果传输，以及浏览器从提交到可播放的总等待时间。每条任务保存实际模型版本和生成参数。断线或重启后先核实进行中的任务状态，再决定重试方式。
