| 接口 | 用途 |
| --- | --- |
| `POST /v1/videos` | 提交生成请求，获取推理任务编号 |

## 一次请求的完整流程

1. 浏览器向 VPS 提交提示词与客户端请求编号。VPS 校验参数并写入 SQLite，立即返回网页任务编号。
2. 后端任务执行器从队列取出任务，通过隧道向 SGLang 提交请求，保存对应的推理任务编号。
3. 浏览器每隔约 2 秒查询 VPS。后端查询推理状态，页面显示排队、生成、传输、完成或失败，以及已经等待的时间。
4. SGLang 完成后，VPS 通过原生内容接口下载 MP4，写入临时文件，验证成功后原子改名并更新任务状态。原始文件保存在 A100 数据盘。
5. 浏览器获得同源视频地址，播放或下载结果。页面刷新后按网页任务编号恢复查询。

请求编号用于避免浏览器重复提交。网络超时后优先核对已知推理任务状态，提交结果不明时记录待核对状态。服务重启后恢复数据库中的任务记录，核实上游任务是否仍存在，再更新状态。失败任务保留错误原因。

## 连接与部署

A100 主动建立到 VPS 的反向 SSH 隧道，已将 A100 的 `127.0.0.1:30010` 转发到 VPS 的 `127.0.0.1:13010`。VPS 后端通过本机地址访问推理服务。SSH 使用专用密钥及受限转发账号，服务管理器负责断线重连。

VPS 的 Nginx 提供静态网页，将 `/api` 和 `/media` 转发到本机 FastAPI。媒体范围响应与缓存读取租约由后端处理。域名未确定时先用可用端口访问 IP 进行验收，域名与 HTTPS 入口随后接入现有 Nginx。构建前端后部署静态产物。后端首版使用单个任务执行器和 SQLite。

代码目录采用 `~/XYZenith_Demo`，运行数据通过项目环境变量指定。用户已选择 VPS 缓存保留24小时、容量上限2GiB，超限时优先回收最早完成的视频，数据库保留记录。密钥和环境配置由部署环境提供，仓库保存模板。
